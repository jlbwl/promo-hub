# 密码历史数据迁移指南

## 概述

本文档说明了如何安全地迁移数据库中的历史明文密码为安全的 bcrypt 哈希密码。

## 背景

由于安全原因，我们已移除了代码中的明文密码后门。为了确保用户数据的安全，需要对 RDS 数据库中的历史明文密码进行安全迁移。

## 风险评估

| 风险项 | 说明 | 优先级 |
|--------|------|--------|
| 历史明文密码 | 数据库中可能存在未加密的密码 | 🔴 高 |
| 默认管理员密码 | 新创建的默认管理员密码需要加密 | 🟡 中 |

## 迁移方案

### 方案一：安全检测 + 强制密码重置（推荐）

**适用场景**：生产环境

**步骤**：

1. **检测明文密码**
   ```bash
   cd /path/to/project
   cd apps/api
   # 或者直接在服务器上运行
   cd /www/wwwroot/promo-hub/api
   ```

2. **执行检测**
   ```bash
   # 需要安装 tsx (如果尚未安装)
   npm install -g tsx
   
   # 检测
   tsx scripts/migrate-passwords.ts --check
   ```

3. **执行迁移**
   ```bash
   tsx scripts/migrate-passwords.ts --migrate
   ```

4. **通知用户**
   - 通过短信通知用户需要重新设置密码
   - 在登录页面添加提示

### 方案二：紧急强制重置所有密码

**适用场景**：安全事件响应

**步骤**：

```bash
tsx scripts/migrate-passwords.ts --force-reset
```

## 迁移脚本使用说明

### 环境变量配置

在服务器上创建 `.env` 文件（或使用系统环境变量）：

```env
DB_HOST=your-rds-host
DB_PORT=3306
DB_USER=your-db-user
DB_PASSWORD=your-db-password
DB_NAME=your-db-name
```

### 脚本功能

| 命令 | 功能 | 说明 |
|------|------|------|
| `--check` | 检测明文密码 | 扫描所有用户表，统计明文密码数量 |
| `--migrate` | 安全迁移 | 将明文密码替换为随机 bcrypt 哈希 |
| `--force-reset` | 强制重置 | 重置所有用户密码（慎用） |

## 迁移后的用户处理流程

### 用户侧

1. 用户登录时：
   - 使用原密码登录失败（正常）
   - 点击「忘记密码」或「短信验证码登录」
   - 通过手机号+短信验证码重新设置密码

### 管理员侧

1. 管理员登录时：
   - 如果是新部署，使用 ADMIN_PASSWORD 环境变量中设置的密码
   - 如果忘记密码，联系技术支持

## 验证迁移结果

执行迁移后，再次运行检测确认：

```bash
tsx scripts/migrate-passwords.ts --check
```

应该看到：

```
✅ 所有密码都是安全的 bcrypt 哈希！
```

## 日志查看

迁移日志会保存在 `logs/` 目录下，文件名格式为：

```
password-migration-YYYY-MM-DD.log
```

## 备份建议

### 迁移前备份数据库：

```bash
# MySQL 备份
mysqldump -u [user] -p [database] > backup_before_migration.sql
```

## 回滚方案

如果迁移出现问题，可以从备份恢复：

```bash
mysql -u [user] -p [database] < backup_before_migration.sql
```

## 后续安全加固建议

1. **密码策略**
   - 密码最小长度 8 位
   - 必须包含大小写字母、数字、特殊字符
   - 定期更换密码（90天）

2. **登录安全**
   - 启用二步验证（2FA）
   - 登录失败次数限制
   - 异地登录提醒

3. **监控**
   - 定期审计登录日志
   - 异常登录检测
   - 安全事件告警

## 常见问题

### Q: 迁移过程中服务需要停机吗？

A: 不需要停机。但建议在低峰期执行，迁移期间用户可能需要重新登录。

### Q: 迁移后旧密码还能用吗？

A: 不能。用户需要通过短信验证码重新设置密码。

### Q: 如何确认迁移成功？

A: 再次运行 `--check` 命令，应该显示 0 个明文密码。

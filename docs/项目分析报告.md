# Promo Hub — 业务推广管理系统 · 项目分析报告

> 一个面向业务推广场景的全栈 SaaS 化管理系统：渠道经理发布产品并推广，用户浏览下单，平台统一审核、结算佣金。
> 项目采用 pnpm Monorepo 架构，「三端一服 + 共享包」，已上线运行于 https://www.jlbtg.cn

---

## 1. 项目概述

| 维度 | 说明 |
|------|------|
| 项目定位 | 业务推广 / 分销结算一体化管理系统 |
| 业务角色 | 管理员（Admin）、渠道经理（Manager）、用户（User）、员工子账号（Employee） |
| 架构形态 | pnpm Monorepo：3 个前端应用 + 1 个 Node.js API 服务 + 1 个共享包 |
| 技术形态 | Vue 3 + TypeScript + Vite / Express + MySQL + Redis |
| 部署形态 | 阿里云 ECS + Nginx(HTTPS) + PM2 + GitHub Actions CI/CD 自动发布 |

## 4. 核心业务流程

### 4.1 订单状态机

```
下单 pending ──审核通过──► 已加款 addedToPayment ──结算──► 已结算 settled
     │
     └──驳回──► rejectReason 记录驳回原因
```

### 4.2 佣金流转

```
订单结算 ──► 生成佣金 pending ──审核──► approved ──打款──► paid
```

### 4.3 订单归属模型（多渠道归因）

| 下单场景 | 归属规则 |
|----------|----------|
| 登录用户直接下单 | 归属当前用户 |
| 通过分享链接下单 | 归属分享者（sharerId，站点内跳转不丢失） |
| 员工子账号下单 | 归属其关联的主用户 |
| 游客下单（无分享者） | 暂不归属，登录后按手机号匹配补挂 |

## 5. 数据模型（核心表）

| 表 | 说明 | 关键设计 |
|----|------|----------|
| `products` | 商品 | 分类快照、规格 JSON、上下架状态与原因 |
| `orders` | 订单 | 软删除、多角色外键（user/manager/employee）、转单字段、**9 个复合索引**优化各角色查询 |
| `commissions` | 佣金 | 与订单关联、三态生命周期时间戳 |

| `employees` | 员工子账号 | 关联主用户、有效期 expiresAt |

Schema 变更统一通过 **Knex migrations** 管理（baseline 0000 起）。

## 6. 安全设计

| 类别 | 措施 |
|------|------|
| 传输安全 | 全站 HTTPS（Nginx + 证书），HSTS 头 |
| 认证 | JWT 双 Token：Access 短期 + Refresh（Redis 持久化，重启不丢）；401 无感续期 + 请求自动重试；单端登录互踢 |
| 授权 | `requireAuth / requireManager / requireAdmin` 三级角色中间件 + 资源级权限校验；统计接口按登录身份强制过滤 |
| CSRF | 全部 POST/PUT/DELETE 接口经 `csrfVerify` 中间件校验，CORS 白名单放行 `X-CSRF-Token` |
| XSS | 商品富文本描述入库前经 `sanitize-html` 白名单清洗 |
| 上传安全 | Mimetype 显式白名单（jpeg/png/webp）+ 角色权限校验（如封面仅经理可传） |
| 注入防护 | 数据库表名校验走 `INFORMATION_SCHEMA` 参数化查询，杜绝表名拼接注入 |
| 安全头 | Helmet 中间件统一安全响应头；接口限流（rateLimit） |
| 信息脱敏 | 手机号/姓名统一脱敏展示（如 张*三），三端共享同一实现 |
| 运维安全 | 缓存清理接口仅 Admin；临时调试路由严禁入生产；部署自动备份 .env 与用户上传文件 |

## 7. 工程化与质量保障

- **Monorepo 共享层**：类型定义、Pinia Store、工具函数（`formatTime / maskPhone / maskName / getErrorMessage`）收敛到 `@promo/shared`，三端零重复实现
- **质量门禁（本地 + CI 双重）**：`pre-commit` 与 deploy workflow 均执行 `ESLint + 全仓 tsc 类型检查（含 API）+ Vitest 227 个单测`，测试不通过禁止部署
- **数据库迁移前置**：CI 部署先执行 `knex migrate:latest` 再重启服务
- **部署流水线**：GitHub Actions → 质量门 → 构建 → SCP 上传（自动备份/恢复 `.env` 与 `data/uploads`）→ 迁移 → PM2 重启 → 健康检查
- **性能优化**：
  - Vite 哈希资源 Nginx 1 年强缓存，`index.html` no-cache 保证发版即时生效
  - Redis + 内存双层缓存（单例 CacheService），数据库连接池 + 查询超时清理
  - 订单表复合索引覆盖各角色高频查询
- **规范治理**：巨型组件全部按「utils + composable + 子组件」拆分（`defineExpose open + emit success` 约定），统一错误消息提取工具，环境感知日志

## 8. 部署架构

```
GitHub main 分支 push
   └─► GitHub Actions
        ├─ 质量门: ESLint · vue-tsc/tsc · Vitest(227 tests)
        ├─ 构建: shared → 三前端 → API
        ├─ 备份: .env / data/uploads
        ├─ SCP 上传 + 目录结构规整
        ├─ knex migrate:latest
        └─ pm2 restart promo-api → /api/health 健康检查

阿里云 ECS (www.jlbtg.cn)
   ├─ Nginx: HTTPS(443) · 静态资源强缓存 · /api 反向代理(路径保真)
   └─ PM2: promo-api (Node 22)  →  MySQL + Redis
```

## 9. 总结

Promo Hub 是一个**业务闭环完整、工程化程度高**的全栈项目：

1. **业务完整**：覆盖「商品发布 → 推广分享 → 下单 → 审核 → 结算 → 佣金打款」全链路，四种角色各得其所；
2. **归因设计**：多渠道订单归属模型（登录 / 分享 / 子账号 / 游客补挂）解决推广分佣的核心归属难题；
3. **安全扎实**：CSRF / XSS / 注入 / 上传 / 越权五大面均有针对性防线，双 Token 认证体验无感；
4. **工程质量**：Monorepo + 共享包 + 227 单测 + 三重质量门 + 自动化部署备份，可持续迭代成本低。
